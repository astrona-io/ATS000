# Section 040: The Astrona CLI And The kubectl Toolkit

Astronaut, you have flown a few missions. Now learn the controls properly. This section covers every step of the `astrona` loop, and the kubectl calls that let you ask a cluster what is going on.

## Modules

This section has two modules and a capstone. Each module has its own playground and one graded mission.

| Module | What you learn | Playground | Graded mission |
| --- | --- | --- | --- |
| [The Astrona Workflow](./module-01/course.md) | `login`, `labs`, `run`, `shell`, `docs`, `use`, `stop`, `start`, `submit`, `reset`, `destroy` | `ats-000-playground-040-01`: the planet `training-lab` with `probe` and `drift` | [Read The Examiner's Hints](./module-01/labs/lab-01/README.md) |
| [The kubectl Toolkit](./module-02/course.md) | `-n`, `-A`, `-o`, `describe`, events, `logs`, `exec`, `port-forward` | `ats-000-playground-040-02`: the planets `harbor` and `harbor-b` | [Write A Note Inside A Ship](./module-02/labs/lab-01/README.md) |
| Capstone | Sweep three planets with the whole toolkit | none | [Capstone: Mission Control Sweep](./capstone/labs/lab-01/README.md) |

The section ends with a [knowledge check](./quiz.yaml). The [final quiz](../final-domain-quiz.yaml) covers all sections.

## What you need

The setup from the first section. Each lab needs about 1.2 GB of memory for the container engine, and the playground should be stopped while a lab runs.
